# XC (platform / cross-cutting) fix status

- F-XC-1: Not fixed — the mock backend still runs in the browser; making role checks enforceable requires a real API server and database (the transport in bundle-src/673.js already expects `POST {backendUrl}/rpc` with a Bearer token, so the client is ready). All other fixes harden the client-side rules so they carry over unchanged when the mock is ported.
- F-XC-2: Fixed — index.html CSP `connect-src` now allows `'self'` and the configured API origin (`https://api.rush-x.xyz`); the config block documents that `backendUrl` must match. Verified: no CSP console errors on boot.
- F-XC-3: Fixed — bundle-src/673.js reads the API origin only from `window.__PLAYORA_CONFIG__.backendUrl`; the `localStorage` overrides and the `localhost:8090` default are gone; with no backend configured the app skips the health probe entirely.
- F-XC-4: Fixed — the hard-coded Neon Auth URL and the swallowed first-attempt fetch were removed from bundle-src/913.js; email sign-in goes only to the configured API.
- F-XC-5: Fixed — demo behaviour (seeded admins/venues, fixed code 123456 and its on-screen hint, auto-approved first organizer) is gated on the explicit `demo: true` flag in the index.html config block, and when that flag is on the dock shows a permanent banner saying the data is seeded and no booking or payment is real. `tools/flows-xcut.mjs` asserts the banner appears with the flag on and is absent with it off. The shipped file keeps `demo: true` because there is no server yet; set it to `false` for a real deployment.
- F-XC-6: Fixed — accounts whose email is listed in `adminEmails` (index.html config) receive the admin role at sign-up and sign-in (bundle-src/631.js `Ne1`), and existing accounts are promoted at hydration. Default list contains `admin@rush-x.xyz`; change it before deploying.
- F-XC-7: Fixed for the client — bundle-src/643.js keeps privileged actions in a separate append-only store (`playora.audit.admin.v1`, 5000 rows) with the full actor id, target id, user agent and structured meta, and the placeholder `ip: "server-captured"` is gone. Read-only screens no longer write into it (see ADM1/ADM2/ORG2). The log is now readable inside the product at `/admin/audit` (new module `bundle-src/new/9003.js`, linked from the admin panel on the profile screen): newest first, filterable by action type and by free text over actor, target and meta, admin-only at both the store and the screen. `tools/rules.mjs` and `tools/flows-admin.mjs` cover the guard, the filters and the rendering. A tamper-evident server-side log still requires the backend.
- F-XC-8: Fixed — `Za` (bundle-src/631.js) throws `E_COULD_NOT_SAVE_CHANGES` / `E_STORAGE_FULL` (localised in en/ar) instead of swallowing write failures; screens surface it through their error handling.
- F-XC-9: Partially fixed — sessions now carry `expires_at` (30 days) and expired sessions are discarded on load (bundle-src/631.js `di`/`li`, bundle-src/913.js). Password hashing and lockout still live on the device; moving them server-side requires the backend.
- F-XC-10: Fixed — added package.json (`serve -s` with SPA rewrites via serve.json), railway.json and nixpacks.toml now install and start that static server; the unused rpc.ts / auth/jwt.ts helpers are documented in CLAUDE.md as server stubs.
- F-XC-11: Partially fixed — the bundle can now be edited and rebuilt from prettified modules (`bundle-src/`, `tools/bundle.py`) with a headless smoke harness (`tools/smoke.mjs`); the original Expo project source is still not in the repository.
- F-XC-12: Partially fixed — see the icon-font trimming note in the final report (unused icon families removed from the inlined asset map); the single-file architecture itself is unchanged.
- F-XC-13: Fixed — OTP codes and throttle counters are persisted (`playora.otp.state.v1`) so a reload cannot reset them, wrong attempts are persisted, and the log SMS provider no longer prints the code.
- F-XC-14: Fixed — shared `useRoleGate` / `GateScreen` / `classifyError` helpers (bundle-src/new/9001.js) with localised "Administrators only" / "Couldn't load this screen" states; applied to every admin screen by the ADM1/ADM2 batches.
